# X 账号批量安全登录功能方案

> 状态：待审核
> 日期：2026-08-21

## 一、项目背景

当前每创建一个浏览器账户，都需要人工打开浏览器并逐个输入 X 用户名、密码和 2FA 验证码。账户规模达到数十或上百时，操作耗时长、容易出错，且缺少统一的进度和异常管理。

建议新增“X 批量登录”功能，在确保账号和凭据安全的前提下，自动完成标准登录步骤，并将异常验证交给人工处理。

## 二、建设方案

管理员批量导入账号资料，每个 X 账号固定绑定一个独立浏览器 Profile。系统按低并发队列逐个登录，成功后保存登录状态，后续无需重复登录。

```text
导入账号资料
→ 创建或绑定浏览器 Profile
→ 检查代理和网络身份
→ 输入用户名、密码
→ 根据 TOTP 密钥即时生成 2FA 验证码
→ 检查登录结果
→ 成功后保存 Profile 和 X 用户名
```

如遇 CAPTCHA、邮箱/短信验证、安全密钥、账号锁定或未知风控页面，系统立即暂停，由管理员人工接管。

## 三、核心功能

- 批量导入 X 用户名、密码、TOTP 密钥及浏览器绑定信息；
- 自动创建或绑定独立浏览器 Profile；
- 自动填写用户名、密码和即时生成的 TOTP 验证码；
- 登录成功后自动识别并保存 `@X用户名`；
- 登录队列支持开始、暂停、继续、取消和单账号重试；
- 展示等待、执行中、成功、失败、等待人工等状态；
- 对 CAPTCHA 和额外验证提供“打开并接管”入口；
- 登录成功后可自动清除密码和 TOTP 密钥，仅保留浏览器登录状态。

## 四、账号安全设计

1. **一账号一 Profile**
   不同账号不共享 Cookie、Token 或浏览器目录。

2. **敏感信息加密存储**
   密码和 TOTP 密钥保存在 macOS Keychain 等安全存储中，业务数据库只保存引用 ID。

3. **敏感信息不外泄**
   密码、TOTP 密钥和验证码不得出现在配置文件、API 返回、日志、错误弹窗或 Git 中。

4. **受控登录节奏**
   默认单账号串行登录，限制提交次数并采用失败退避，避免快速重复请求。

5. **稳定登录环境**
   每个账号固定代理、地区、时区、语言和设备 Profile，登录过程中不自动切换。

6. **不绕过平台安全机制**
   模型只辅助识别页面和异常，不自动破解 CAPTCHA，也不绕过邮箱、手机或账号风控验证。

## 五、系统实现方式

采用“确定性登录流程 + 模型辅助识别 + 人工异常接管”：

- 程序状态机负责标准登录步骤、TOTP 生成、重试和结果确认；
- 模型负责识别未知页面、判断异常类型并生成管理员可读说明；
- 低置信度、挑战页或额外验证统一停止自动操作，转人工处理。

这种方式比让模型自由操作整个登录流程更稳定、可测试、可审计。

## 六、管理台设计

新增“X 批量登录”页面，主要包含：

- 账号批量导入和校验；
- 浏览器 Profile 绑定；
- 登录任务队列和总体进度；
- 单账号步骤、耗时、尝试次数和脱敏错误；
- 人工接管、继续检测、跳过和取消；
- 凭据清除和登录历史记录。

## 七、实施计划

### 第一阶段：安全 MVP

- 批量导入和校验；
- Keychain 保存密码及 TOTP 密钥；
- 标准用户名、密码、TOTP 自动登录；
- 默认单并发队列；
- 登录成功检测和用户名回写；
- CAPTCHA/额外验证人工接管；
- 敏感信息脱敏和重试限制。

### 第二阶段：运营增强

- CSV/XLSX 模板；
- 暂停恢复和断点续跑；
- 失败原因统计和审计报表；
- 可配置并发、执行时间和代理分组；
- 模型辅助识别更多异常页面。

## 八、预期收益

- 将大量账号首次登录从逐个手工操作改为队列化处理；
- 管理员只需处理少量异常验证和挑战页面；
- 登录成功后长期复用 Profile，降低重复登录成本；
- 统一管理凭据、进度、失败原因和审计记录；
- 减少手工输入错误和敏感信息泄漏风险。

## 九、主要风险

| 风险 | 应对措施 |
|---|---|
| X 页面结构变化 | 状态机与选择器回归测试，失败时人工接管 |
| 代理质量或地区变化 | 登录前检测并固定登录环境 |
| 批量并发触发验证 | 默认单并发，限制最大并发和重试次数 |
| 凭据泄漏 | Keychain、统一脱敏、操作审计和自动清除 |
| CAPTCHA/额外验证 | 明确暂停，不尝试绕过，由人工处理 |
| 平台条款和账号风险 | 上线前完成合规审核并限制使用范围 |

## 十、待审批事项

1. 是否批准建设“X 批量登录”功能；
2. 是否批准使用 macOS Keychain 保存密码和 TOTP 密钥；
3. 登录成功后是否默认自动清除敏感凭据；
4. 第一阶段是否固定为单账号串行执行；
5. 是否允许 CSV/XLSX 导入敏感字段及其销毁策略；
6. 是否已完成 X 服务条款和内部账号管理制度的合规评估。

## 十一、建议结论

建议批准第一阶段安全 MVP。该方案可以显著减少大量账号首次登录的重复人工操作，同时通过独立 Profile、安全凭据存储、低并发和人工接管控制风险。

上线前需完成凭据安全和合规审核，并明确：系统只自动执行标准登录流程，CAPTCHA 和额外风控验证仍需人工处理，也不能保证所有账号均可全自动登录成功。
